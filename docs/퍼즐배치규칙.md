# 퍼즐 배치와 행동횟수 규칙

2026-11-13. 현재 6×6~10×10 소형 방과 새 기믹을 기준으로 한다. [좌표 배치와 화면](방크기조정.md), `data/stages.json`을 함께 확인한다.

## 설계 목표

플레이어가 짧은 경로와 작업 순서를 찾아야 통과하는 퍼즐로 만든다. 난이도는 재료 회수 순서, 운반물의 임시 용도, 복구 후 통로 차단에서 만든다. 같은 운반을 반복시키는 것만으로 난이도를 높이지 않는다.

## 배치 규칙

1. 방마다 핵심 판단을 먼저 정하고 장치를 놓는다. 새 기믹은 하나씩 소개하고, 이미 배운 기믹과 결합한다.
2. 벽과 장애물에는 경계, 구역 분리, 통로 차단, 운반 거리 절약 중 설명할 수 있는 역할이 있어야 한다. 우회만 길게 만드는 벽을 난이도 수단으로 추가하지 않는다.
3. 순서 퍼즐의 함정·초소는 실제 병목에 둔다. 복구 전에는 필요한 재료를 회수할 수 있고, 복구 후에는 그 구역에 다시 들어갈 수 없도록 구성한다.
4. 정상 풀이에서는 모든 복구를 끝낸 뒤 빈손으로 출구에 도달할 수 있어야 한다. 잘못된 순서로 스스로 길을 막은 상태는 되돌리기로 복구한다.
5. 해당 방의 핵심 장치를 생략한 풀이가 행동 제한 안에 들어오면 배치를 다시 설계한다. 장치가 이동을 절약한다면 그 절약이 실제 최소 행동 수에 반영되어야 한다.
6. 재료는 목표에 필요한 수량만 둔다. 함정마다 부품 1개, 병사마다 뼈 묶음 2개가 필요하다. 장식은 통행 불가 벽칸에 둔다.
7. 최소 풀이만 정답으로 강제하지 않는다. 같은 규칙과 행동 제한을 만족하는 다른 순서도 허용한다.

## 행동횟수 규칙

**2~8번 방의 제한 = 검증한 최소 행동 수 + 2회.** 1번 튜토리얼은 무제한이다. 2회의 여유는 짧은 왕복 한 번 또는 불필요한 내려놓기·줍기 한 번 정도다.

| 행동 | 차감 |
| --- | ---: |
| 성공한 한 칸 이동 | 1회 |
| 줍기·내려놓기·설치·뼈 납품·병사 배치·레버 가동·투입구 전송·거울 회전·인부 배치·회수·잔해 밀기 | 각각 1회 |
| 두 번째 뼈 납품과 병사 자동 조립 | 합쳐서 1회 |
| 문 개폐·광선 갱신·애니메이션 | 추가 차감 없음 |
| 벽에 부딪히거나 조건이 맞지 않는 입력·경로 미리보기·이동 취소 | 0회 |
| 되돌리기 | 직전 상태와 사용한 1회를 함께 복구 |
| 재시작 | 초기 상태와 전체 횟수 복구 |

마우스로 5칸 떨어진 바닥을 한 번 클릭해도 실제 5칸 이동에는 5회가 든다. 도착 후 상호작용은 별도다. 마지막 행동으로 출구 복귀까지 완료하면 성공한다. 횟수 소진 후에는 되돌리기와 재시작이 가능하다.

## 현재 방별 기준

| 방 | 크기 | 핵심 판단 | 최소 행동 | 제한 |
| --- | --- | --- | ---: | ---: |
| 1 | 6×6 | 함정을 설치해 건넌 뒤 레버 가동 | 12 | 무제한 |
| 2 | 7×7 | 두 구역의 뼈 회수 후 초소 배치 | 33 | 35 |
| 3 | 8×8 | 두 함정 너머 재료 회수 후 초소·레버 마무리 | 45 | 47 |
| 4 | 7×7 | 잔해로 발판을 눌러 문 열기 | 32 | 34 |
| 5 | 8×8 | 거울로 문 개방, 투입구로 뼈 운반 절약 | 35 | 37 |
| 6 | 8×8 | 앞면을 맞춘 거울 2회 연속 반사로 문 개방 | 43 | 45 |
| 7 | 8×8 | 인부 배치 후 부품 회수, 인부를 회수해 초소 배치 | 41 | 43 |
| 8 | 10×10 | 거울 3회 연속 반사·투입구·인부·잔해 결합 | 99 | 101 |

행동 수는 방의 길이를 나타내며 난이도 순위가 아니다. 새 기믹을 소개하는 방은 앞선 복합 퍼즐보다 작아도 된다. 장치는 필요한 접근·밀기 공간을 확보하고 높은 문 뒤에 가리지 않게 배치한다.

거울은 E / Space 한 번에 90도씩 네 방향을 순환한다. 청록색 화살표가 앞면이며, 앞면에서 들어온 빛만 반사한다. 뒷면은 빛을 차단한다. 한 바퀴에는 행동 4회가 든다. 6번은 거울 회전 총 4회, 8번은 총 7회가 필요하다.

## 배치 변경 후 검사

1. 기믹 종류·수와 복구 재료 수를 유지하고 장치 연결 좌표와 장식을 새 지도에 맞춘다.
2. `python tools/solve_levels.py --stage N --output <결과.json>`으로 최단 풀이를 구한다. 탐색 상한에 도달한 결과를 최단 증명으로 취급하지 않는다.
3. `tests/solutions.py`에 최소 행동·풀이를 등록하고 2~8번 제한을 최소+2회로 설정한다.
4. 최단성과 기믹 생략 불가, 행동 소진·되돌리기, 튜토리얼·클릭·실제 표시를 검사한다.

```powershell
python tools/solve_levels.py --check --check-mechanics --output docs/balance-report.json
python -m unittest discover -q
```

탐색기는 실제 `Game.act`의 유효 이동·상호작용·내려놓기를 탐색한다. 문·복구물의 차단을 완화한 운반 거리 하한을 사용한다. 인부 한 명으로 문 안의 부품을 꺼내야 하는 경우 인부 운반·배치·회수의 필수 비용을 추가한다. 거울문 안의 부품은 필요한 거울 회전 수를 하한에 포함한다. 필수 장치 방문 거리는 운반 제약을 제거하고 투입구 이동까지 완화한 별도 하한으로 계산한다. 두 거리 하한은 합산하지 않고 큰 값만 사용한다. 작은 함정·발판·투입구·인부·연속 반사 방의 전체 상태 그래프와 대조해 하한과 최단성을 검사한다. 수신 방향 조합이 하나뿐인 방에서는 이미 맞춘 거울을 다시 틀어 문을 닫는 입력을 제외한다. 빛에는 피해나 다른 목표가 없어 이 입력은 최단 풀이를 개선할 수 없다. 탐색기는 게임 실행 중에는 호출하지 않는다.

4번 잔해·발판, 5번 거울·투입구, 6번 거울, 7번 인부, 8번 잔해·거울·인부·투입구를 각각 금지하면 제한 안에 완료할 수 없다. [탐색 보고서](balance-report.json)에 최소 풀이와 입력 파일의 SHA-256을 보존한다.

SDL dummy/software 입력·화면과 자동 검사를 사용했다. 사람의 초회 플레이 난이도와 실제 물리 입력은 아직 측정하지 않았다.
