# 퍼즐 배치와 행동횟수 규칙

2026-11-16. [현재 좌표 배치와 방별 제한](방크기조정.md), `data/stages.json`을 함께 확인한다.

## 설계 목표

플레이어가 짧은 경로와 작업 순서를 찾아야 통과하는 퍼즐로 만든다. 난이도는 재료 회수 순서, 운반물의 임시 용도, 복구 후 통로 차단에서 만든다. 같은 운반을 반복시키는 것만으로 난이도를 높이지 않는다.

## 배치 규칙

1. 방마다 핵심 판단을 먼저 정하고 장치를 놓는다. 새 기믹은 하나씩 소개하고, 이미 배운 기믹과 결합한다.
2. 벽과 장애물에는 경계, 구역 분리, 통로 차단, 운반 거리 절약 중 설명할 수 있는 역할이 있어야 한다. 우회만 길게 만드는 벽을 난이도 수단으로 추가하지 않는다.
3. 순서 퍼즐의 함정·초소는 실제 병목에 둔다. 복구 전에는 필요한 재료를 회수할 수 있고, 복구 후에는 그 구역에 다시 들어갈 수 없도록 구성한다.
4. 정상 풀이에서는 모든 복구를 끝낸 뒤 빈손으로 출구에 도달할 수 있어야 한다. 잘못된 순서로 스스로 길을 막은 상태는 되돌리기로 복구한다.
5. 해당 방의 핵심 장치를 생략한 풀이가 행동 제한 안에 들어오면 배치를 다시 설계한다. 장치가 이동을 절약한다면 그 절약이 실제 최소 행동 수에 반영되어야 한다.
6. 재료는 목표에 필요한 수량만 둔다. 함정마다 부품 1개, 초소마다 뼈 묶음 2개 또는 조립된 해골 1명이 필요하다. 소품은 통행 불가 벽감에 두고, 벽등은 바닥에 면한 벽면에 붙인다.
7. 최소 풀이만 정답으로 강제하지 않는다. 같은 규칙과 행동 제한을 만족하는 다른 순서도 허용한다.

## 행동횟수 규칙

1번 튜토리얼은 무제한이다. 2~8번의 행동 제한과 최소 풀이의 차이는 방에 따라 4~15회다. 전체 제한에 도달하면 되돌리기나 재시작으로 복구한다.

| 행동 | 차감 |
| --- | ---: |
| 성공한 한 칸 이동 | 1회 |
| 줍기·내려놓기·설치·뼈 납품·병사 배치·레버 가동·투입구 전송·거울 회전·기록 시작·잔해 밀기 | 각각 1회 |
| 두 번째 뼈 납품과 병사 자동 조립 | 합쳐서 1회 |
| 문 개폐·광선 갱신·애니메이션 | 추가 차감 없음 |
| 벽에 부딪히거나 조건이 맞지 않는 입력·경로 미리보기·이동 취소 | 0회 |
| 되돌리기 | 직전 상태와 사용한 1회를 함께 복구 |
| 재시작 | 초기 상태와 전체 횟수 복구 |

마우스로 5칸 떨어진 바닥을 한 번 클릭해도 실제 5칸 이동에는 5회가 든다. 도착 후 상호작용은 별도다. 마지막 행동으로 출구 복귀까지 완료하면 성공한다. 횟수 소진 후에는 되돌리기와 재시작이 가능하다.

## 현재 방별 기준

행동 수와 방 크기는 [현재 배치 표](방크기조정.md)에 기록한다.

| 방 | 핵심 판단 |
| --- | --- |
| 1 | 시험로를 건너 옆칸의 시운전 레버 가동 |
| 2 | 두 작업대 중 하나에 뼈를 모으고 묘실 입구 봉쇄 |
| 3 | 두 레버 중 출구로 돌아갈 수 있는 쪽에서 봉쇄 |
| 4 | 감방을 차례로 열고 두 뼈로 무기고 통로 유지 |
| 5 | 뼈를 투입구로 보낸 뒤 거울을 돌려 출구 개방 |
| 6 | 뼈를 추로 쓴 뒤 회수하고 차광 블록으로 광로 전환 |
| 7 | 같은 부품으로 두 발판을 차례로 눌러 해골을 꺼내고 인부의 길을 개방 |
| 8 | 두 인부의 발걸음을 따로 기록하고 함정 가동 후 출구로 가는 광로 개방 |

행동 수는 방의 길이를 나타내며 난이도 순위가 아니다. 새 기믹을 소개하는 방은 앞선 복합 퍼즐보다 작아도 된다. 장치는 필요한 접근·밀기 공간을 확보하고 높은 문 뒤에 가리지 않게 배치한다.

작업대와 고정 거울은 통행을 막는다. 상하좌우 한 칸 옆에서 E / Space로 납품하거나 회전한다. 이동 거울은 위에서 돌린다. 거울은 한 번에 90도씩 돌며 화살표 방향으로 빛을 내보낸다. 한 바퀴에는 행동 4회가 든다.

기록석을 밟으면 표시된 걸음 수만큼 이동 방향을 기록한다. 수리공은 마지막으로 밟은 칸에 남는다. 기록 완료 후 첫 유효 행동부터 해골 인부가 자기 위치에서 기록 방향을 한 걸음씩 따른다. 이동할 칸이 막혀 있으면 인부는 제자리에 남고 해당 걸음은 소모된다. 재생이 끝난 뒤 인부가 일반 발판 위에 남아 있으면 문이 열린 채 유지된다. 기록석마다 한 번만 기록할 수 있다. Z로 위치와 기록을 함께 되돌린다.

화면 하단에는 기록한 방향, 인부가 재생한 걸음 수, 연결문의 현재 상태를 표시한다. `통과`는 지금 들어갈 수 있는 문이고, `통과 중`은 수리공이 문 칸을 빠져나갈 때까지 닫힘을 미룬 상태다.

기록 길이는 `worker_links[].steps`, 인부의 방 시작 위치는 `worker_links[].worker`에서 정한다. 여러 문이 같은 기록석을 쓰면 `station`, `steps`, `timed`, `worker`를 같게 두고 문마다 별도 문양을 연결한다.

## 배치 변경 후 검사

1. 핵심 기믹과 복구 재료 수를 확인하고 장치 연결 좌표와 장식을 새 지도에 맞춘다.
2. `python tools/solve_levels.py --stage N --output <결과.json>`으로 최단 풀이를 구한다. 탐색 상한에 도달한 결과를 최단 증명으로 취급하지 않는다.
3. `tests/solutions.py`에 최소 행동과 풀이를 등록한다. 방의 길이와 장치 전환 횟수에 맞춰 여유를 정하고 `data/stages.json`에 제한을 설정한다.
4. 최단성과 기믹 생략 불가, 행동 소진·되돌리기, 튜토리얼·클릭·실제 표시를 검사한다.

```powershell
python tools/solve_levels.py --check --check-mechanics --output docs/balance-report.json
python -m unittest discover -q
```

탐색기는 실제 `Game.act`의 유효 이동·상호작용·내려놓기를 탐색한다. 문·복구물의 차단을 완화한 운반 거리 하한을 사용한다. 인부 한 명으로 문 안의 부품을 꺼내야 하는 경우 인부 운반·배치·회수의 필수 비용을 추가한다. 거울문 안의 부품은 필요한 거울 회전 수를 하한에 포함한다. 필수 장치 방문 거리는 운반 제약을 제거하고 투입구 이동까지 완화한 별도 하한으로 계산한다. 두 거리 하한은 합산하지 않고 큰 값만 사용한다. 작은 함정·발판·투입구·인부·연속 반사 방의 전체 상태 그래프와 대조해 하한과 최단성을 검사한다. 수신 경로에서 항상 같은 방향을 쓰는 거울은 맞춘 상태에서 다시 돌리는 입력을 제외한다. 빛에는 피해나 다른 목표가 없어 이 입력은 최단 풀이를 개선할 수 없다. 탐색기는 게임 실행 중에는 호출하지 않는다.

4번 잔해·발판, 5번 잔해·거울 밀기와 회전·투입구·발판, 6번 차광 블록·발판, 7번 인부·발판, 8번 차광 블록·거울·인부를 생략하면 제한 안에 완료할 수 없다. [탐색 보고서](balance-report.json)에 최소 풀이와 입력 파일의 SHA-256을 보존한다.

SDL dummy/software 입력·화면과 자동 검사를 사용했다. 사람의 초회 플레이 난이도와 실제 물리 입력은 아직 측정하지 않았다.
