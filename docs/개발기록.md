## 1. 이번 작업의 목표와 결과

개발 시작 시 저장소에는 README, 기획서, 발표 PPT만 있었고 게임 실행 코드는 없었다. 원본 PPT 8장의 내용을 다시 읽고 Python·pico2d, 2.5D 복구 퍼즐, 입문 3개를 포함한 8개 방이라는 방향을 유지했다.

이번 결과물은 기본 규칙을 실제로 연결해 검증할 수 있는 입문방 3개다. 부품 운반부터 함정 설치와 가동, 뼈 납품과 병사 조립·배치, 출구 복귀까지 플레이할 수 있다. 이동 경로를 잘못 막았을 때 되돌리기와 재시작으로 복구한다.

본편 8개 완성이나 최종 난이도 검증을 완료한 것은 아니다. 현재 방은 규칙 검증용이며, 그래픽은 임시 도형이고 사운드는 없다. 세부 규칙을 확정된 원작 설정으로 간주하지 않도록 상세 계획에 결정의 근거와 변경 범위를 구분했다.

발판·연결문, 뼈 투입구, 벨트의 처리 순서와 점유 충돌 정책도 상세 계획에 작성했다. 이 장치들은 현재 코드에 포함하지 않았다.

## 3. 기능별 개발 내역

### 3.1 스테이지 데이터와 실행 전 검사

대상 파일: [game/levels.py](../game/levels.py), [data/stages.json](../data/stages.json), [tests/test_levels.py](../tests/test_levels.py).

`load_levels()`는 JSON을 읽어 정적 `Level` 정보를 만든다. 지도와 게임 진행 상태를 분리해 재시작 때 원본 데이터를 다시 사용할 수 있다. 기본 데이터 경로는 `__file__`에서 계산하여 터미널의 현재 폴더에 의존하지 않는다.

읽는 시점에 다음 오류를 거절한다.

- 빈 방 목록, 잘못된 필드·문자열·지도 형식, 중복 ID.
- 8~12 범위 밖 크기, 서로 다른 행 길이, 알 수 없는 기호, 열린 테두리.
- 시작·출구가 없거나 여러 개인 지도, 복구 목표가 없는 지도.
- 함정 수와 부품 수 불일치, 초소 수와 뼈 묶음 수 불일치.
- 함정이 있는데 레버가 없거나 초소가 있는데 작업대가 없는 지도.

이 검사는 형식과 재료 수를 보장한다. 방의 해결 가능성은 별도의 정답 행동열로 확인한다. `Level`의 초기 물건 사전은 게임 시작 때 복사하며, 게임 코드는 원본을 수정하지 않는다.

### 3.2 이동·운반과 전체 상태 되돌리기

대상 파일: [game/model.py](../game/model.py), [tests/test_game.py](../tests/test_game.py).

`Game.act()`는 행동을 임시 상태에 적용한다. 성공한 경우에만 이전 상태를 기록하고 새 상태를 채택한다. 실패 시에는 메시지만 바뀌고 위치, 자원, 목표, 행동 수, 기록은 유지한다.

`State`에는 위치, 운반물, 바닥 물건, 설치 위치, 가동 여부, 배치 병사, 작업대의 뼈, 행동 수, 완료 여부가 들어간다. `undo()`는 이 상태 전체를 복원한다. `restart()`는 초기 데이터로 새 상태를 만들고 기록을 비운다.

이동은 상하좌우 한 칸이며 벽·보드 경계·가동 함정·배치 병사로의 진입을 막는다. 바닥 물건 위는 걸을 수 있고 줍기는 별도 행동이다. 내려놓기는 물건과 장치가 없는 일반 바닥에서만 허용해 덮어쓰기를 방지한다.

### 3.3 함정·병사 복구와 완료

대상 파일: [game/model.py](../game/model.py).

- 부품을 들고 파손 함정에서 상호작용하면 부품을 소비하고 설치 상태가 된다. 설치만 한 함정은 통과 가능하다.
- 빈손으로 레버를 조작하면 모든 함정의 설치 여부를 검사한 뒤 함께 가동한다. 가동 후에는 함정 칸으로 들어갈 수 없다.
- 뼈를 처음 납품하면 작업대에 한 묶음을 보관한다. 두 번째 납품은 보관분과 운반분을 병사 하나로 바꾸고 손에 들게 한다.
- 초소에 병사를 배치하면 손을 비우고 해당 초소를 완료 처리한다. 배치 직후 그 칸에서 나갈 수 있지만 다시 들어갈 수 없다.
- 모든 복구와 빈손 출구 조건이 충족되면 완료된다. 이후 일반 행동을 막고 undo·restart·다음 방 입력을 허용한다.

조립의 재료 소비와 병사 생성은 하나의 행동이다. 되돌리기 한 번으로 작업대의 첫 묶음과 손에 든 둘째 묶음을 함께 복원한다. 가동과 배치의 취소 역시 전체 상태 복원을 사용한다.

### 3.4 입문방 세 개

| 방 | 학습과 배치 | 검증용 해결 행동 수 |
| --- | --- | --- |
| 첫 번째 복구 | 개방된 8×8 공간에서 부품·설치·레버·출구 학습 | 14 |
| 해골 병사의 귀환 | 개방된 8×8 공간에서 뼈 두 번 납품·병사 배치 학습 | 26 |
| 돌아올 길을 남겨라 | 단일 연결부에 초소와 함정을 두어 재료 확보·복귀 순서 판단 | 43 |

행동 수에는 이동과 상호작용을 모두 포함한다. 이는 테스트에 기록한 한 가지 해결 경로의 길이이며, 최단 해답이나 사람의 플레이 시간이라는 뜻은 아니다.

세 번째 방에서는 오른쪽에 뼈 두 묶음, 왼쪽에 작업대·레버·출구가 있다. 함정을 먼저 가동하면 오른쪽 재료를 회수할 수 없으며, 병사를 배치한 뒤 오른쪽으로 나가면 왼쪽으로 복귀할 수 없다. 해결 가능 경로와 조기 가동 후 막힘·undo 복구를 검사했다.

### 3.5 pico2d 화면과 조작

대상 파일: [game/view.py](../game/view.py), [main.py](../main.py), [requirements.txt](../requirements.txt).

1280×900 창에 사선 보드, 플레이어, 물건·장치, 복구 현황, 운반물, 행동 수, 현재 칸 안내를 표시한다. 도형과 한글 문구를 함께 사용해 색만으로 상태를 구별하지 않게 했다.

`view.py`는 키 입력을 모델의 행동 이름으로 전달한다. 완료 후 Enter는 새 방의 `Game`을 만들고, 마지막 방에서는 첫 방으로 돌아간다. 표시 과정에서 복구 규칙을 직접 수정하지 않는다.

Windows의 맑은 고딕을 사용하고, `DUNGEON_FONT`로 다른 한글 폰트 경로를 지정할 수 있다. 폰트 파일과 외부 이미지 자산은 저장소에 포함하지 않았다. pico2d를 실행 경로에서만 불러오므로 데이터와 논리 검사는 그래픽 패키지 없이도 수행할 수 있다.

CLI는 시작 방 지정, 데이터 검사, 지정 프레임 후 종료를 지원한다. 잘못된 방 번호나 프레임 수는 실행 전에 거절한다. 정확한 명령과 키 표는 README에서 관리한다.

### 3.6 회귀 검사와 자동 검사 구성

대상 파일: [tests/](../tests), [GitHub Actions 설정](../.github/workflows/tests.yml).

표준 라이브러리 `unittest`로 모델과 로더를 검사한다. 외부 테스트 프레임워크와 그래픽 초기화가 필요하지 않다. 정상 경로의 최종 결과뿐 아니라 매 행동의 자원 보존과 기록, 실패 전후 전체 상태도 비교한다.

[선택 SDL 검사](../tests/smoke_window.py)는 실제 창을 만들고 SDL 키 이벤트를 넣어 입력 처리부터 렌더링, 모델, 다음 방, 종료까지 재생한다. 줍기·내려놓기·두 undo 키·재시작을 먼저 검사하고 세 방을 완료한 뒤 첫 방으로 돌아온다. 운영체제의 물리 키보드 입력 전달을 대체하는 검사는 아니다.

GitHub Actions에는 Windows/Python 3.14와 Ubuntu/Python 3.10의 데이터 검사, 논리 검사, 문법 검사를 구성했다. 원격 실행 상태는 [Actions 기록](https://github.com/sanu1227/2DGP-PROJECT/actions)에서 확인한다. CI는 그래픽 창을 열지 않는다.

논리 테스트가 다루는 시나리오는 다음과 같다.

1. 벽 이동, 빈손 내려놓기, 맞지 않는 상호작용, 손이 찬 상태 등 실패 시 상태와 기록 유지.
2. 복구 전체 흐름의 부품·뼈 환산량 보존, 모든 행동의 되돌리기, 완료 후 일반 행동 잠금.
3. 여러 함정 중 일부만 설치한 상태의 레버 거절, 전체 가동, 가동 취소 후 통과.
4. 첫 뼈 납품 뒤 재시작, 원본 데이터와 별도 게임 상태의 독립성.
5. 실제 세 방의 해결, 완료 되돌리기, 재완료와 재시작.
6. 세 번째 방 조기 가동으로 통로 차단, undo 후 뼈 회수 재개.
7. 잘못된 JSON 구조·메타데이터·지형·재료·누락 파일·문법 오류.
8. 다른 현재 작업 폴더에서도 기본 데이터 로드.

### 4.3 실제 창 관찰과 입력 검증의 한계

첫 방의 실제 화면을 캡처해 보드, 한글 제목·안내, 현황, 하단 키 안내를 확인했다. Windows 자동 입력으로 방향키 이동과 Backspace 되돌리기의 화면 갱신을 확인했다. 창의 닫기 버튼으로 종료되는 것도 확인했다.

같은 자동 입력 도구로 보낸 문자 키·Space·Escape는 검사 중 pico2d의 키 이벤트로 관찰되지 않았다. 별도 이벤트 기록으로 방향키는 전달되고 문자 키는 전달되지 않는 차이를 확인했다. SDL 텍스트 입력을 끈 임시 검사에서도 문자 키가 전달되지 않아, 제품 코드에 임의의 우회 처리를 추가하지 않았다.

SDL 이벤트를 직접 넣는 선택 검사에서는 같은 키 매핑의 이동·상호작용·내려놓기·undo·restart·다음 방·Escape가 모두 통과했다. **운영체제 자동 입력 도구의 전달 문제와 실제 사용자 키보드 동작을 동일하게 단정하지 않는다.** 사람이 물리 키보드로 전체 입력을 확인하는 작업과 재미·난이도·장시간 관찰은 남아 있다.

## 5. 커밋과 원본 보존

### Windows CI 출력 인코딩 보정

첫 원격 실행에서 Ubuntu의 데이터·논리·문법 검사는 통과했다. Windows는 한글 방 이름을 출력하는 `--check` 단계에서 기본 `cp1252` 인코딩으로 인해 실패했다. 데이터 로드 뒤 출력에서 발생한 오류였다.

CI 환경에 `PYTHONIOENCODING=utf-8`을 지정해 stdout·stderr를 GitHub 로그의 UTF-8과 맞췄다. 별도 프로세스에서 `cp1252` 실패와 UTF-8 성공을 재현해 원인을 확인했다. 게임 규칙과 데이터는 변경하지 않았다. 최신 원격 검사 결과는 Actions 기록에서 확인한다.

기능별로 상세 설계, 스테이지 데이터와 검사, 복구 모델과 검사, 화면·실행, SDL 흐름 검사, CI, 실행 문서를 구분한다. 각 커밋 본문에 구현 이유와 검증 범위를 기록한다. 정확한 커밋 해시는 `git log --oneline` 또는 [커밋 기록](https://github.com/sanu1227/2DGP-PROJECT/commits/main)에서 확인한다.

작업 시작 전부터 존재한 PPT 수정분, 원본 MP4, 발표영상 보정 폴더는 이번 게임 코드 커밋에 포함하지 않는다. 파일을 덮어쓰거나 삭제하지 않고 작업 폴더에 보존한다. 원격 대상은 기존 `origin`의 `main`이며 강제 푸시를 사용하지 않는다.

## 6. 남은 작업의 우선순위

| 우선순위 | 작업 | 완료 판단 |
| --- | --- | --- |
| 1 | 실제 키보드로 모든 조작과 세 방 플레이 확인 | 입력 누락·방향 혼동·문구 오해 기록 |
| 2 | 입문방 동선·조립 수량·배치 규칙 관찰 | 반복 운반 부담과 규칙 이해도에 따라 수정 |
| 3 | 발판·연결문, 투입구를 개별 구현 | 점유·출력 충돌·undo 검사 통과 |
| 4 | 대기 행동과 한 턴 벨트 처리 구현 | 한 칸 제한·동시 충돌·자원 보존 통과 |
| 5 | 4~8단계 조합과 전체 진행 구성 | 각 방 정답·잘못된 순서·복구 경로 확보 |
| 6 | 최종 아트·사운드·진행 저장·배포 | 새 실행 환경과 실제 사용자 관찰 통과 |

전체 플레이 시간 60~70분과 PPT 구간 합계 69~105분의 차이는 아직 해소하지 않았다. 시간은 실제 첫 플레이를 측정한 뒤 조정한다.

## 7. 시각 에셋 1차 제작 — 2026-11-08

[시각 에셋 1차 팩](../assets/art_v1/README.md)에 투명 PNG 44개와 아틀라스 3장을 추가했다. 환경 12종, 운반물·장치 16종, 청록색 수리공 4방향×4자세 16프레임으로 구성한다. 캐릭터와 화풍은 이번에 제안한 1차 디자인이다. 현재 기획의 함정 파손·설치·가동, 병사 운반·배치, 레버·출구 상태를 구분한다. 후속 발판·투입구·벨트는 그림만 준비했다.

내장 `image_gen`으로 원본 아틀라스 3장을 생성하고, 원본 PNG와 전체 프롬프트를 `assets/art_v1/sources/`에 보존했다. `tools/art/build.mjs`는 실제 반환 해상도를 읽어 분할하고, 256×256 PNG와 2:1 타일 간격·발밑 기준점을 정렬한다. 제작용 sharp는 `tools/art/`에만 설치했으며 게임의 Python 의존성은 변경하지 않았다.

전체 목록, 바닥 연결, 실제 입문 3번 방 데이터를 이용한 조립 예시를 이미지로 만들고 육안으로 확인했다. 원본 알파, 셀 경계 잘림, 출력 여백, 파일 크기·RGBA8·SHA-256 검사를 통과했다. `tools/art/check.py --window`는 실제 pico2d/SDL에서 개별 이미지 44개와 아틀라스 3장을 로드하고, 개별 그리기 44개와 아틀라스 클립 44개를 비교했다. RGBA 채널의 최대 차이는 1/255였다.

게임 렌더러·모델·스테이지·입력·PPT·영상은 변경하지 않았다. `main.py`에는 아직 그림을 적용하지 않았다. 걷기는 생성된 두 키포즈이며, 최종 움직임·운반물 합성·작은 화면에서의 가림·물리 키보드 플레이 검증은 남아 있다. UI·음향·효과 애니메이션도 후속 범위다.
